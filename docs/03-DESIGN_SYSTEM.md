# 1. Design Philosophy

DataDock is a premium desktop-inspired cloud storage platform.

The design should prioritize:

- Simplicity
- Clarity
- Speed
- Elegance
- Consistency

Every interface should reduce cognitive load and help users focus on managing their files.

The application should feel like a polished desktop product running inside the browser.

DataDock should feel:

- Premium
- Professional
- Minimal
- Intelligent
- Fast
- Modern
- Trustworthy
- Calm
- Elegant

Avoid making the interface feel:

- Playful
- Cartoonish
- Overly colorful
- Distracting
- Over animated

---

# 4. Design Principles

## Simplicity

Every screen should contain only the information users need.

---

## Consistency

Use consistent spacing, typography, colors, and interactions across the application.

---

## Clarity

Users should instantly understand:

- Where they are.
- What they can do.
- What happens next.

---

## Visual Hierarchy

Important information should naturally attract attention.

Secondary information should remain available without competing for focus.

---

## Delight

Small details matter.

Hover effects.

Loading animations.

Transitions.

Micro interactions.

These should make the interface feel polished without becoming distracting.

---

# 5. Color System

## Primary Color

A modern blue used for actions, highlights, links, and focus states.

---

## Neutral Palette

Use neutral gray tones for:

- Backgrounds
- Borders
- Text
- Cards
- Dividers

The interface should rely more on spacing and hierarchy than color.

---

## Success

Green

---

## Warning

Amber

---

## Error

Red

---

## Information

Blue

---

## Rules

Do not overuse accent colors.

Use color to communicate meaning.

Maintain sufficient contrast for accessibility.

---

# 6. Typography

Typography should feel clean and modern.

## Headings

Bold

Strong hierarchy

Easy to scan

---

## Body Text

Readable

Comfortable line height

High contrast

---

## Labels

Short

Consistent

Clear

---

## Rules

Avoid excessive font weights.

Avoid decorative fonts.

Prioritize readability over style.

---

# 7. Spacing System

Use an 8-point spacing system.

Base spacing values:

- 4px
- 8px
- 12px
- 16px
- 24px
- 32px
- 48px
- 64px

Spacing should remain consistent throughout the application.

---

# 8. Border Radius

Rounded corners should feel modern without being exaggerated.

Examples:

- Buttons
- Cards
- Inputs
- Dialogs
- Dropdowns

Maintain consistent border radius across all components.

---

# 9. Shadows

Use soft shadows.

Avoid harsh shadows.

Shadows should provide depth without drawing attention.

Use stronger shadows only for:

- Dialogs
- Popovers
- Floating elements

---

# 10. Iconography

Use Lucide React icons.

Rules:

- Consistent stroke width.
- Minimal style.
- Avoid mixing icon libraries.

Icons should support the interface rather than dominate it.

---

# 12. Motion & Animation

Animation should enhance usability.

Never animate simply for decoration.

---

## Landing Page

Inspired by:

Apple × Trionn × Vercel

Use:

- GSAP
- Framer Motion

Animation ideas:

- Hero storytelling
- Scroll-based reveals
- Background motion
- Mouse interactions
- Section transitions
- Premium loading sequences

Goal:

Create a memorable first impression.

Users should think:

> "Wow."

---

## Dashboard

Inspired by:

Raycast × Linear

Use:

- Framer Motion

Animation examples:

- Sidebar expansion
- Hover states
- Upload progress
- Context menus
- Modal transitions
- File preview animations
- Toast notifications

Goal:

The application should feel incredibly polished while remaining fast.

---

## Animation Rules

Every animation must serve one or more purposes:

- Guide attention
- Indicate state changes
- Provide user feedback
- Improve perceived performance
- Add subtle delight

Avoid:

- Excessive motion
- Long animation durations
- Flashy effects
- Motion that slows productivity

Performance always takes priority.

---

# 13. Theme Guidelines

DataDock should support:

- Dark Theme
- Light Theme

Dark mode is the primary experience.

Both themes must maintain:

- Consistent spacing
- Consistent hierarchy
- Accessible contrast
- Identical interactions

Users should never lose functionality when switching themes.
